# Miki Writer

*[English](README_EN.md)*

**把一个已经想清楚的选题，直接变成能发出去的稿子——小红书、朋友圈、公众号、口播稿/视频脚本、README，一条流程走完。**

## 能做什么

- **动笔前先自己找材料**：去 Obsidian Vault 里翻已经整理好的每日记录，找和这个选题相关的内容，看看当时是怎么想、怎么说的，不等你现喂。
- **五类事实分开处理**：仓库可验证的事实、你自己说过的话、第三方反馈、AI 的推断、会过时的数据分开标注，不把一句话包装成板上钉钉的结论，也不编不存在的细节。
- **材料不够就主动问**：找不到相关记录、或记录撑不起一篇完整表达时，先问会改变主线的问题，问完再写，不硬凑。
- **不套固定模板**：每篇现场识别一条主导推进线（事情怎么变化的、认知怎么变化的、怎么取舍的），结构从具体事实里长出来。
- **保留你的声音**：自然口语、自嘲、真实情绪都留着，不自动统一润色成一种"高级感"腔调。
- **去 AI 味两阶段校准**：先列出哪里像 AI 写的，再从最深层的地方开始改，不做机械的关键词反转。
- **终稿保护**：说"这是终稿"之后只提建议、不再动正文；被删掉或否决的内容不会悄悄再加回来。
- **轻量文风自进化**：手改完一篇稿子后对比改动前后的差异更新文风记忆，只从真实改动里学。
- **多格式交付**：小红书/抖音图文、朋友圈文案、公众号长文、口播稿/视频脚本/提词器稿、技术长文、GitHub README（中英双语），各自有对应的格式规范和合规自查。
- **技术长文一键多平台分发**：一篇主稿改写适配到公众号和小红书，事实和结论不变，只调整表达方式和篇幅；素材不局限于代码仓库，也包括实验数据、链接评论反馈、口述说明。
- **配图建议**：小红书图文、朋友圈、技术长文会附带配图思路——AI 生图提示词、该截哪张图、信息图该包含什么，只出文字建议，不生成或选择实际图片。
- **小说（虚构创作）**：把一个想法梳理成前提、世界观、人物，再定大纲、逐章推进。唯一不受"事实边界"约束的模式。
- **交互式网页（HTML）**：技术长文的网页版、README 里的可运行演示、独立介绍页，产出单个自包含的 `.html` 文件（可以有点击展开、tab 切换、图表交互），双击就能打开，不自动部署。

## 必须配合 Obsidian 使用

写作前主动去 Obsidian Vault 里找素材是这个 Skill 最核心的一步，目前**没有**做其他笔记软件的适配。想接到别的工具上，需要自己改写 `SKILL.md` 里读取素材的部分。

## 快速开始

### 第一步：装 Obsidian

打开 [obsidian.md](https://obsidian.md)，下载对应系统的安装包，创建一个新的 Vault（存笔记的文件夹）。界面可能随版本变化，以官方说明为准。

### 第二步：把这个 Skill 接到你的 AI 工具上

- **Claude**（网页版/桌面版）：在设置里找 Skills / Capabilities 入口，按引导添加这个文件夹。
- **Claude Code**：把文件夹放进项目的 `.claude/skills/`（或用户级 skills 目录），自动识别。
- **Codex 或其他支持 Skill 机制的工具**：按该工具自己的说明接入。
- **在 Obsidian 里直接用**：装一个能把 Obsidian 和 AI 工具连起来的社区插件，配置好 API access。

### 第三步：开始用

直接用自然语言说你要写什么，比如"帮我把这个项目写成一篇小红书笔记"；也可以点名"用 miki-writer 帮我写……"，确保触发的是这个 Skill。

## 它不会做的事

- 不自动发布、群发、登录平台后台或操作账号密码——需要你单独明确授权。
- 不编造经历、数据、评论或引语；许可证以仓库实际文件为准。
- 不写医疗/法律/理财担保性建议，不碰政治敏感、仇恨对立、骚扰动员内容。
- 材料不够时不替你编一套完整立场，会先问你。

## 关于隐私和可移植性

`SKILL.md` 里出现的路径、文件名都是使用者自己的个人配置，不是写死的——分享给别人时，对方按自己的 Vault 结构调整即可，不会暴露原使用者的笔记内容或目录组织方式。`references/ip-signature.md`（署名话术）和 `references/author-voice.md`（文风记忆）里的内容是原使用者自己的，拿去用时换成你自己的。
